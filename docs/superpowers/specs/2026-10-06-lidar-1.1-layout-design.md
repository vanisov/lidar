# Lidar 1.1: Layout

1.1 adds five layout tools. The roadmap's "Debug detectives" group moves to 1.2, and the later releases move up by
one (see the Releases table in `2026-10-02-lidar-design.md`).

## Goals

- Show how a page is laid out: its flex and grid containers, a design column grid, its breakpoints, and every element
  box.
- Find elements by CSS selector.
- Keep every 1.0 rule: nothing runs before activation, `Esc` restores the page exactly, no Preact in the hot path,
  styles only through `adoptedStyleSheets`, no text below 11 px, no new dependencies, no network requests.

## Features

### Flex / grid overlay (automatic)

- In Measure, hovering a grid or flex container draws its layout in addition to the usual size and box-model overlay.
  There is no new dock button.
- **Grid:** column and row track lines, gaps hatched, and line numbers (1-based, and also at the far edge). Track sizes
  come from the computed `grid-template-columns` / `grid-template-rows`, which the browser resolves to px. So
  `repeat()`, `fr`, `auto` and `minmax()` show their used sizes.
- **Flex:** an outline on each item, the gaps between items hatched, and a line break marker where `flex-wrap` starts a
  new line.
- Only the hovered (or pinned) container is drawn. Nested containers are not drawn.
- **Pinned:** the full overlay stays on, and the panel gets a "Layout" section:
  - Grid: template columns and rows, gaps, `grid-auto-flow`, alignment.
  - Flex: direction, wrap, gaps, `justify-content`, `align-items`.
  - Each value can be copied like the existing ones.
- `display: inline-flex` and `inline-grid` count as containers. `display: contents` children are skipped.

### Column grid (`G`)

- A dock toggle, styled like Rulers. The state is saved in settings.
- Draws translucent accent-colored columns over the whole viewport height.
- Settings: columns 1–24 (default 12), gutter 0–200 px (default 24), side margin 0–400 px (default 24), max width
  0–4000 px (default 0, meaning full width). When the max width is set, the grid is centered.
- Values are sanitized like the existing settings.

### Breakpoints (on the top ruler)

- Whenever the rulers are on, each viewport breakpoint is a tick on the horizontal ruler at its x position. The current
  range (between the nearest ticks around the viewport width) is tinted.
- Hovering a tick shows its query text, for example `@media (min-width: 768px)`. A breakpoint whose x is beyond the
  viewport isn't drawn. The current range covers it.
- Sources: every `CSSMediaRule` in `document.styleSheets`, recursing through `@import`, `@supports` and `@layer`. Only
  `min-width`, `max-width` and range syntax (`width >= 768px`) are read. `em` and `rem` convert at 16 px (media queries
  ignore the root font size). Container queries are ignored.
- Cross-origin sheets throw on `cssRules`. They are counted, and the ruler tooltip ends with "N stylesheets couldn't be
  read". Lidar never fetches them.
- Rescanned when Lidar opens and when the number of stylesheets changes (not when rules are added to an existing sheet).

### X-ray (`X`)

- A dock toggle, saved in settings. It outlines every rendered element that intersects the viewport, 1 px, with the
  accent color at low alpha.
- Skips Lidar's host, `display: contents`, and elements with no client rects.
- It reuses the Spread box cache, so it does not go into shadow roots.
- Scroll and resize rebuild the boxes immediately. DOM mutations rebuild them at most every 250 ms.

### Selector search (`/`)

- `/` opens a search bar above the dock. Typing updates the matches on each input (`querySelectorAll` on the document,
  in try/catch).
- All matches in the viewport are outlined. The current match gets a solid outline. A counter shows "1 of N", or
  "No matches", or "Not a valid selector".
- ↑/↓ move the current match and scroll it into view (`block: 'nearest'`).
- Enter pins the current match and closes the bar. `Esc` in the bar closes just the bar. `Esc` anywhere else still
  closes Lidar.
- Matches inside Lidar's own host are excluded.

## Architecture

- **`core/paint.ts`:** owns one `<canvas>` in the overlay layer, sized to the viewport × `devicePixelRatio`.
  `paint(scene)` clears it and draws rects, hatched rects and lines. The scene is plain data.
  - Text (line numbers, tick labels, pills) stays as DOM nodes from the fixed pool, so it stays crisp and readable.
  - The overlay's rAF loop builds the scene only when something is dirty.
- **`core/layout.ts` (pure):** `gridLines(rect, computedTracks, gaps)` and `flexLines(itemRects, direction)` return the
  geometry the overlay draws.
- **`core/breakpoints.ts` (pure parsing, plus a thin scanner):**
  - `parseQuery(text) → { min?, max? }[]`
  - `scanSheets(document) → { points, unreadable }`
- **`core/xray.ts`:** `visibleBoxes(root, viewport, skip) → DOMRect[]`, a TreeWalker that prunes subtrees that are
  fully off-screen when they are `overflow: hidden`.
- **`core/search.ts`:** `findMatches(selector, skip) → Element[] | 'invalid'`.
- **Store:**
  - `search` signal: `{ open, query, index }`.
  - `settings` gains `grid: boolean`, `xray: boolean`, and `columns: { count, gutter, margin, maxWidth }`.
- **`tools/registry.ts`:** adds Grid (`g`, toggle), X-ray (`x`, toggle) and Search (`/`).
- **`keys.ts`:** `Esc` closes search first when it is open. Search handles its own arrows because it is a Lidar input.
- **UI:**
  - `SearchBar.tsx` and a Layout section in `Panel.tsx`.
  - Column fields in `SettingsView.tsx`.
  - New icons in `icons.tsx`.

## Performance

- The existing perf test (5,000 nodes, no long tasks while hovering) must also pass with X-ray on and while scrolling.
- An X-ray scan reads one `getClientRects` per element and nothing else.
- Canvas repaints happen only on dirty frames.

## Testing

- **Vitest:** `layout.ts` (fixed, fr and auto tracks; gaps; wrapped flex lines; row and column directions),
  `breakpoints.ts` parsing (min/max, range syntax, em, nested rules, ignoring non-width queries), settings sanitize for
  the new fields.
- **Playwright** (fixture gains a grid section, a wrapping flex row, and a `@media` rule):
  - Hovering the grid draws a canvas scene with the expected track count (exposed through a test-only `data-` scene
    summary on the canvas).
  - `G` and `X` toggle and persist.
  - The ruler shows the fixture's breakpoint tick.
  - Search: type, count, arrow, Enter pins; invalid selector message; `Esc` closes the bar but not Lidar.
  - `Esc` leaves the DOM unchanged with every new tool on.
  - The perf test with X-ray on.

## Out of scope

- Debug detectives (now 1.2).
- Inspecting grid areas by name, subgrid-specific drawing, and container-query breakpoints.
- Search inside iframes or closed shadow roots.
